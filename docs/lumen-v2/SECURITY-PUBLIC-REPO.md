# 公开仓库安全规范

## 1. 可以公开

- 产品定位、流程、UI 规格和非敏感技术架构；
- 脱敏的测试命令与摘要；
- 合成或已授权的测试图片；
- 不含客户、密钥和供应商账户信息的截图；
- 错误码、性能区间和架构决策。

## 2. 不得公开

- `.env*`、API Key、密码、JWT/加密 Secret、私钥；
- Provider 配置 JSON，即使字段经过部分遮挡；
- 真实客户图片、聊天、订单和联系方式；
- 原始生产 Prompt 或可能包含客户特征的输入；
- 完整请求体、base64 图片、Authorization header；
- 数据库导出、对象存储签名 URL；
- 模型权重和未授权训练集。

## 3. Evidence 规则

每项证据必须说明：

- 来源：合成 / 授权 / 脱敏；
- 对应任务和验收项；
- 生成命令；
- 是否包含生产数据：必须为否。

终端日志优先保存为 `.txt`，手工移除路径中的用户名、Token 和账户 ID。截图优先 WebP/JPEG，裁掉浏览器账号、书签、系统托盘和环境变量。

## 4. 提交前检查

```bash
node scripts/check-lumen-collab.mjs
npm run lint
npm test
npm run build
```

并人工检查：

- `git diff --cached`
- 新增二进制文件；
- `.env` 和配置备份；
- 网络面板截图；
- 图片 EXIF；
- 真实客户姓名和人像。

## 5. 发现泄露

一旦发现真实密钥进入公开提交：

1. 立即撤销/轮换密钥；
2. 暂停发布和合并；
3. 清理 Git 历史，而不是只删除最新文件；
4. 在私有渠道记录事故，不在公开仓库复述密钥；
5. 更新安全门禁和回归检查。
