# 01｜当前产品与 UI 深度审计

## 1. 总体判断

光砚已经具备“技术演示可运行”的骨架，但尚未形成稳定的“工作台产品”。当前最突出的问题不是颜色、圆角或图标，而是 **产品对象、任务流程、系统状态和编辑语义没有统一**。

当前界面把多模型、工具、Prompt、参考图和对比画布放在一个页面中，但没有清晰回答四个问题：

1. 我现在在处理哪个项目和哪张照片？
2. 本次修改的目标是什么？
3. 系统正在做什么，失败后如何恢复？
4. 哪一个结果是已确认版本？

## 2. 视觉审计基线

参考：`references/current-ui-annotated.jpg`。

| 编号 | 当前问题 | 影响 | 优先级 |
|---|---|---|---|
| 1 | Provider/模型占据顶部一级位置 | 把底层实现复杂度转嫁给用户 | P0 |
| 2 | 左栏只有图标、无稳定文字标签 | 新用户无法快速建立工具心智 | P0 |
| 3 | 画布没有项目、资产和版本语义 | 用户只看到一张图，不知道工作状态 | P0 |
| 4 | 右侧栏过窄，层级与分组弱 | 参数难扫描，长内容被迫滚动 | P0 |
| 5 | 大色块按钮缺少稳定主操作文案 | 不知道会直接覆盖还是生成候选 | P0 |
| 6 | “应用”与 Prompt“提交”并存 | 主任务冲突，产生两套调用心智 | P0 |
| 7 | 参考图 0/14 直接暴露 | 大多数用户不理解 14 张的作用 | P1 |
| 8 | 结果/原图/对比是平级开关 | 对比模式与版本管理脱节 | P0 |
| 9 | 画布操作零散、无说明 | 缩放、适应和外部打开缺乏一致性 | P1 |
| 10 | 生成结果可能改变构图、人物或纹理 | 对专业人像场景是核心质量风险 | P0 |

## 3. 产品层问题

### 3.1 目标用户冲突

当前叙事同时包含：

- 专业修图师工作台；
- 客户“先体验后问价”的营销入口；
- 多模型 API 管理器；
- 技术作品集演示。

这四种用户对权限、复杂度、输出质量和成本的要求完全不同。继续在一个页面中叠加只会增加复杂度。V2 采用 Pro/Preview 双模式，先把 Pro 工作台做完整。

### 3.2 技术卖点替代了用户价值

“4 个 Provider、12 个模型、工厂模式”适合作品集说明，不适合成为日常界面。用户关心的是“自然”“保留本人”“速度快”“成本低”。模型需要成为系统路由策略，而不是首屏决策。

### 3.3 工具集合缺少完整流程

当前六个工具是并列菜单，但专业工作不是随机点击工具，而是：

> 诊断 → 基础人像 → 色彩 → 局部清理 → 审核 → 导出

缺少项目、任务阶段、版本、采用状态和导出记录，导致工具功能再多也难以形成可复用流程。

## 4. 交互层问题

### 4.1 滑块承诺了不存在的确定性

底层是生成式模型，滑块数值 42 与 43 不会稳定产生可预测差异。0—100 精细滑块让用户误以为它类似 Lightroom 参数。建议改为 5 档强度，并把“身份锁定、自然度、构图保护”作为明确的质量控制项。

### 4.2 主操作冲突

参数面板有“应用”，Prompt 区又有“提交”。两者看起来都可能触发模型请求。V2 只保留一个底部固定 CTA“生成预览”，所有参数、参考图和补充要求共同组成一次编辑配方。

### 4.3 空状态不具备引导能力

当前空状态只有小型拖拽框，右侧仍显示大量不可用控件。V2 空状态应提供：

- 上传照片；
- 使用示例项目；
- 最近项目；
- 隐私与文件要求；
- 对右侧控件进行隐藏或禁用说明。

### 4.4 生成过程不可解释

模型调用可能持续数十秒。界面必须显示阶段而不是伪造百分比：上传、分析、生成、后处理、保存。用户应能够离开当前面板、取消、重试，刷新后恢复任务。

### 4.5 历史记录不是版本系统

localStorage 历史可以回退，但缺少版本名称、缩略图、父版本、采用状态和生成元数据。V2 用底部版本条呈现原图和每次结果，并保留版本链。

## 5. 功能缺口

### P0 缺口

- 项目化工作区；
- 单一生成操作；
- 智能模型路由；
- 明确生成状态和错误恢复；
- 版本条与采用状态；
- 持久化恢复；
- 身份/构图/自然度保护；
- 生产安全配置。

### P1 缺口

- 局部画笔/蒙版；
- 多候选结果；
- 预设同步和批量任务；
- 参考图角色化；
- 分享审阅和批注；
- AI 诊断建议。

### P2 缺口

- 多人协作；
- 批量场景一致性；
- 自动质量检查；
- 模型效果基准与自动 A/B；
- 面向印刷和交付的色彩管理。

## 6. 技术与安全问题

1. Vercel Serverless 的临时文件目录不适合作为持久数据库。
2. 图像和历史只依赖 localStorage 时，刷新、换设备或 URL 失效会造成不可恢复。
3. 90 秒 Serverless 请求与 100 秒客户端超时非常脆弱，缺少任务 ID 和恢复机制。
4. `AUTH_PASSWORD=changeme` 和 JWT 默认值在生产环境必须 fail-fast，不能静默兜底。
5. `cors()` 无限制放开、50MB JSON base64 上传会放大安全与性能风险。
6. Provider Key 加密是正确方向，但需要用户隔离、轮换、审计和持久存储。
7. 图片应明确保存周期、EXIF 处理、删除策略和签名 URL。

## 7. 基准产品启示

- Photoshop 把 AI 动作放在上下文任务栏，并保持非破坏式结果；启示是“当前任务优先于全量工具列表”。
- Evoto 以完整摄影工作流、预设同步和批量处理为核心；启示是“专业价值来自可复制工作流，而不是单张 Demo”。
- Photoroom 的局部涂抹式 Retouch 降低对象移除门槛；启示是“局部编辑必须直接作用于画布”。
- Canva 将复杂编辑压缩为添加、擦除、替换等结果导向动作；启示是“用户选择目标，不应先选择模型”。
