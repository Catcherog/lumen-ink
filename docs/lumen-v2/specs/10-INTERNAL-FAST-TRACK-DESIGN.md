# 10｜内部稳定版加速推进设计

> 状态：用户已批准并完成书面规格复核  
> 日期：2026-07-18  
> 目标：优先让 3 人内部团队稳定使用；公开发布级能力与非必要问题统一延期。

## 1. 决策摘要

采用“连续执行、保留内部硬门”的推进方式：

```text
STORAGE-001 快速决策门
  → PERSIST-001 持久化与可恢复生成闭环（包含内部安全底线）
  → 3 人内部稳定可用验收
  → ROUTING-001 / 完整 HARDEN-001 / 非关键体验优化延后
```

不把 STORAGE-001 与 PERSIST-001 合成同一未冻结实现，也不并行修改共享 API、状态与配置文件。加速来自压缩选型材料、减少中间交接、扩大 Trae 连续执行包和延后非必要问题，而不是跳过数据一致性、安全底线或自动化验证。

## 2. 成功定义

内部稳定版必须让 3 人团队完成：

1. 创建项目并上传合成或授权图片；
2. 创建 original Asset 与不可变 V0；
3. 创建 GenerationJob，并只展示服务端真实状态；
4. 生成成功后按 Asset → Version → Job `succeeded` 的顺序落库；
5. 失败或取消不创建成功 Version；
6. 刷新后恢复项目、活动版本与未完成任务；
7. 支持查看、对比、激活、采用、重试、best-effort 取消；
8. 删除项目时清理元数据和对象；
9. 旧 history 先备份，再显式导入可恢复条目；
10. 凭据、上传、跨域、登录和日志满足内部使用安全底线。

以下不属于内部稳定版完成条件：智能模型路由、客户 Preview、多工作区 IAM、完整公开发布加固、非关键 UI 微调、动画、性能美化和覆盖率数字优化。

## 3. 阶段 A：STORAGE-001 快速决策门

### 3.1 必须交付

- 比较两个可执行的完整方案，而不是多个零散产品列表；
- 每个方案覆盖数据库、对象存储、签名 URL、任务状态、80—100 秒执行策略、Windows 本地替代、成本、迁移、备份、删除和回滚；
- 使用合成数据完成 Project、Asset、Job 创建/更新、适配器重建后读取和级联删除 PoC；
- 输出并通过 PERSIST-001 所需的 Repository、ObjectStore、UnitOfWork 和 JobExecutor 合约测试；
- `docs/lumen-v2/storage-options.md` 给出唯一推荐方案、评分矩阵、依赖版本、环境变量清单和回滚方式。

### 3.2 压缩规则

- 只保留两个完整候选方案；第三方案仅在前两者均不满足硬条件时补充；
- 不制作生产迁移、不上传真实客户图、不接入正式账号数据；
- 不追求完整管理后台、监控仪表盘或供应商抽象层；
- PoC 只证明接口、恢复、删除和长任务策略可执行，不证明生产容量。

### 3.3 冻结权限

- 若推荐方案不需要新增付费账号、不可逆迁移或提高既定预算，GPT 可依据 PoC、合约测试和评分矩阵直接冻结技术方案；
- 若需要付费账号、信用卡、生产数据迁移或不可逆供应商绑定，状态转为 `awaiting_user_decision / nextActor=user`；
- 冻结前 PERSIST-001 不得写生产实现；冻结后 Trae 可在同一连续执行指令下立即进入 PERSIST-001，无需重新讨论已冻结接口。

## 4. 阶段 B：PERSIST-001 连续扩大执行包

PERSIST-001 继续使用现有设计和 12 项实施计划，但改为一次连续执行：Trae 按任务级 TDD 和独立 commit 推进，中途不因普通绿灯结果反复交接；只在硬停止条件出现时暂停。

### 4.1 保持的核心范围

- Project、Asset、Version、GenerationJob 领域模型；
- 上传/V0、生成/版本、刷新恢复、取消、重试、幂等、删除；
- 服务端 Repository 与业务服务边界；
- 真实版本条和 Job 状态 UI；
- 旧 history 备份、只读检查与显式导入；
- 旧 `/api/edit` 受控兼容层；
- 故障矩阵、脱敏证据和统一工程门禁。

### 4.2 合并进入 PERSIST-001 的内部安全底线

这些安全项直接保护新持久化主链，不能推迟到公开发布：

- Production/内部部署缺少认证 secret、JWT secret、Provider 凭据时 fail-fast；
- 删除默认密码、默认 JWT 和加密 Key fallback；
- 登录失败限流；
- 内部部署 CORS allowlist；
- 上传 MIME、文件大小、像素和解码校验；
- Provider Key 不返回前端；
- 项目、Job、health、edit/detect 日志脱敏；
- 项目级联删除与孤立对象诊断/清理；
- 对上述边界增加自动化安全回归测试。

这些内容作为 PERSIST-001 的最后三个实施单元追加，不单独等待一次 GPT 规划交接。完整公开发布 Gate D 仍保留在 HARDEN-001。

## 5. 延期清单

新增 `docs/lumen-v2/FAST-TRACK-DEFERRED.md` 作为唯一延期登记表。仅登记满足以下条件的问题：

- 不导致数据丢失、错误成功版本、刷新不可恢复或资产残留；
- 不泄露凭据、客户图片、未脱敏日志或工作区数据；
- 不阻断 3 人内部核心流程；
- 有明确归属任务、严重度和最迟处理阶段。

默认延期：

- ROUTING-001 全部能力：质量/均衡/速度策略、fallbackChain、高级模型锁定、成本档位；
- 客户 Preview 和多工作区 IAM；
- 完整公开发布开关、生产运维仪表盘、容量与压力优化；
- S2/S3 视觉、动画、快捷键和非核心交互；
- 不影响核心行为的代码组织、命名、抽象和覆盖率优化；
- 24 张完整视觉质量集的非阻塞扩展测试，内部版先使用最小授权/合成代表集。

S0/S1、安全底线和核心一致性问题不得进入延期表。

## 6. 连续执行与交接规则

### 6.1 Trae 可连续执行

- STORAGE-001 内部的方案研究、PoC、合约测试、报告与证据；
- 方案冻结后的 PERSIST-001 Task 1—12；
- PERSIST-001 追加的内部安全底线实施单元；
- 每个可独立回滚单元使用单独 commit，最终统一 push 和回传。

### 6.2 仅在以下情况停止

1. 需要用户购买、授权账号、提供预算或执行不可逆迁移；
2. 存在数据丢失、密钥泄漏、客户数据暴露或权限绕过；
3. STORAGE PoC 无法证明适配器重建后恢复、Job 状态持久化或级联删除；
4. PERSIST 出现失败/取消创建成功 Version、刷新不可恢复、重复请求创建重复版本或删除残留对象；
5. 统一 lint、typecheck、test、build、安全扫描失败，且失败属于当前任务；
6. 当前实现要求修改已冻结的 Provider/API/存储协议或扩大到公开发布架构。

普通 P2、非核心 S2/S3、文案和 UI 微调只登记，不停止连续执行。

## 7. 验收策略

### STORAGE-001 快速验收

- 只审两个方案的硬条件、评分依据、PoC 原始证据、合约测试、成本/账号需求和回滚；
- 不审供应商宣传材料完整度，不要求第三方案；
- 无付费或不可逆决策时，GPT 一轮内给出 `MVP_PASS` 或带明确 P0 的 `MVP_FAIL`。

### PERSIST-001 + 内部安全底线验收

- 风险驱动审计上传/V0、Job 状态机、成功事务、失败/取消、刷新恢复、版本操作、删除和安全边界；
- 独立重跑聚焦测试、全量测试、lint、前后端 typecheck、build 和公开仓库安全扫描；
- S0=0、S1=0；只允许有归属和期限的 S2/S3 延期；
- 不要求 ROUTING、Preview、完整生产发布或非关键体验优化完成。

## 8. Git 与工作区边界

- 先由 Trae 单独提交并推送 FLOW-001 GPT 验收控制面文件和任务移动；
- STORAGE-001 与 PERSIST-001 使用各自任务分支、任务 ID、报告和 PR，不把两个任务混为一个提交历史；
- 连续执行指令可以覆盖两个阶段，但 STORAGE 冻结仍是 PERSIST 的内部硬门；
- 不提交当前工作区既有无关修改；每次 `git add` 使用精确路径；
- GPT 负责设计、冻结和验收，commit/push 由 Trae 执行。

## 9. 回滚与失败策略

- STORAGE 方案未冻结时，删除 PoC 资源即可回到无生产变更状态；
- PERSIST 新 API/UI 使用 feature flag，旧 `/api/edit` 保持受控兼容；
- 数据迁移优先向前修复，不依赖破坏性 downgrade；
- 回滚不得删除用户资产或旧 history 备份；
- 后台执行器不可用时，可关闭新生成入口并保留项目和版本只读恢复。

## 10. 下一步

书面规格复核通过后：

1. 更新 STORAGE-001 为快速决策任务包；
2. 扩展 PERSIST-001 计划，加入内部安全底线实施单元；
3. 创建 `FAST-TRACK-DEFERRED.md`；
4. 输出一个可复制的 Trae 连续执行入口；
5. 不改变当前 `STATE.json` 的 `STORAGE-001 / ready_for_trae / nextActor=trae`，直到 Trae 正式开始执行。
