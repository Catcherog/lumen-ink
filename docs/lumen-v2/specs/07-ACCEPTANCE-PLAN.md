# 07｜验收计划与发布门禁

## 1. 验收原则

GPT 只依据可重复证据验收：代码差异、运行截图、测试结果、网络记录、构建日志和明确的已知问题。Trae 声称“完成”不构成通过。

## 2. 每轮固定回传

1. 任务 ID、分支和提交；
2. 修改文件列表；
3. 关键决策和未完成项；
4. lint、typecheck、test、build 的完整命令与结果；
5. 适用时提供 1440×900、1280×800 截图；
6. 核心流程连续截图或短视频；
7. 已知问题、回滚方式；
8. 更新后的 `SESSION-HANDOFF.md`。

## 3. 阶段门禁

### Gate BASE-001

- [ ] client lint 0 error、0 warning；
- [ ] client/server/root test 命令存在；
- [ ] client 至少包含 2 个有效测试；
- [ ] server 至少包含 2 个有效测试；
- [ ] root test 能统一执行；
- [ ] client/server typecheck 通过；
- [ ] root build 通过；
- [ ] 当前可见行为无变化；
- [ ] 补齐 PromptInput、Color、Liquify、Cleanup、RemovePeople 面板事实表。

### Gate UI-001

- [ ] `VITE_EDITOR_V2=false` 时 Legacy 行为不变；
- [ ] 本地/Preview 可开启 V2；
- [ ] Production 默认关闭；
- [ ] 1440×900 和 1280×800 无横向溢出；
- [ ] 顶栏不显示 Provider/模型；
- [ ] 左栏每个入口始终有文字标签；
- [ ] EMPTY 与 READY 布局可用；
- [ ] 底部版本条仅显示明确“尚未启用版本持久化”的占位，不伪造版本；
- [ ] 本轮没有改 Provider、API 或存储。
- [ ] 兼容期旧 CTA 若存在，必须记录为 FLOW-001 待办，且 V2 不进入 Production。

### Gate FLOW-001

- [ ] 页面只剩一个模型调用主按钮“生成预览”；
- [ ] 所有工具参数进入 EditRecipe；
- [ ] 人像参数为五档；
- [ ] 保护项默认开启；
- [ ] “补充要求”没有独立提交；
- [ ] Prompt 编译器版本可追踪；
- [ ] 现有 Provider 输出行为未被无意改变。

### Gate STORAGE-001

- [ ] 至少比较 2 个可执行方案；
- [ ] 明确元数据、图片、任务状态各自的真相来源；
- [ ] 明确 Vercel 适配和后台任务策略；
- [ ] 提供最小 PoC 证据，不接入生产数据；
- [ ] 给出成本、迁移、备份、删除和回滚；
- [ ] GPT/用户冻结方案后才能进入 VERSION-001。

## 4. P0 最终发布门禁

### Gate A：工程

- [ ] install、lint、typecheck、test、build 全通过；
- [ ] 无阻断 console error；
- [ ] 无密钥或真实客户数据进入仓库；
- [ ] Production feature flag 切换有回滚步骤。

### Gate B：核心流程

- [ ] 空状态可创建项目并上传；
- [ ] 上传后创建原始版本；
- [ ] 只有一个“生成预览”主操作；
- [ ] 生成显示真实阶段；
- [ ] 成功创建新版本；
- [ ] 失败可重试且不污染版本；
- [ ] 刷新后恢复项目、任务和版本；
- [ ] 版本可查看、对比、激活和采用；
- [ ] 导出来源版本明确。

### Gate C：视觉与交互

- [ ] 1440×900 无横向溢出；
- [ ] 1280×800 可完成核心流程；
- [ ] 左栏文字标签稳定；
- [ ] 右栏主按钮固定可见；
- [ ] 对比缩放和平移同步；
- [ ] 空状态不显示大量无效控件；
- [ ] 键盘 focus 可见。

### Gate D：安全

- [ ] Production 缺少安全变量时启动失败；
- [ ] Provider Key 不返回前端；
- [ ] 未授权无法读取工作区数据；
- [ ] 上传有 MIME、大小和像素限制；
- [ ] CORS 使用 allowlist；
- [ ] health 和日志不泄露配置；
- [ ] 删除项目清理派生资产。

## 5. 标准视觉质量测试集

使用 24 张授权或合成图片，不使用真实客户私密照片。

| 类别 | 数量 | 目的 |
|---|---:|---|
| 正面单人自然光 | 4 | 身份和自然度 |
| 侧脸/半侧脸 | 3 | 轮廓与五官稳定 |
| 眼镜/帽子/头饰 | 3 | 遮挡保留 |
| 发丝跨脸/复杂边缘 | 3 | 局部细节 |
| 低光/逆光 | 3 | 光影与噪点 |
| 中式服装/复杂纹理 | 3 | 服装和文化元素 |
| 多人 | 2 | 人脸选择与误改 |
| 手靠近脸部 | 2 | 手指和边缘保护 |
| 大尺寸高分辨率 | 1 | 性能与导出 |

人工评分：身份保留、自然度、指令遵循、构图保留、局部边缘、可交付性，各 1—5 分。

以下任一项直接失败：

- 身份明显变化；
- 五官或手指明显畸变；
- 服装图案/关键物体被无要求改变；
- 输出损坏或尺寸异常；
- 无法恢复上一版本。

## 6. 缺陷分级

- S0：数据丢失、密钥泄露、项目不可恢复、主流程不可用。
- S1：错误创建成功版本、取消无效、对比错位、身份保护默认失效。
- S2：布局、文案、状态或边界条件问题。
- S3：动画、细节、快捷键和非核心体验。

P0 发布要求：S0=0、S1=0；S2 有明确清单和计划。
